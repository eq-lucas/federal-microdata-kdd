ANÁLISE DETALHADA DO CÓDIGO DO REPOSITÓRIO FIES
=================================================

Arquivo gerado para explicar, em linguagem natural, o que o código faz, como as etapas se conectam e qual é a teoria por trás das partes mais técnicas, especialmente os pipelines do scikit-learn, as regressões logísticas, as árvores de decisão, as métricas e as bases ABT.

Observação honesta: esta análise é estática. Isto significa que o código foi lido, organizado e interpretado arquivo por arquivo. Eu não executei o pipeline completo com os microdados brutos oficiais, porque isso exigiria os arquivos originais posicionados na estrutura esperada. Portanto, quando digo que a lógica está correta, estou falando da implementação e do fluxo do código, não de uma auditoria executada do começo ao fim com os dados reais.

Também não vou insistir aqui na lista de pequenos ajustes que você pediu para ignorar. O foco deste arquivo é: entender o que cada parte faz, como faz e por que faz.

=================================================
1. VISÃO GERAL DO REPOSITÓRIO
=================================================

O repositório é um pipeline de pesquisa. Ele pega dados brutos do FIES e do Censo da Educação Superior, organiza esses dados em várias camadas, gera bases analíticas, treina modelos estatísticos/de aprendizado de máquina e exporta tabelas/figuras para o artigo.

A lógica geral é esta:

1) data/01_raw
   Dados brutos baixados dos portais oficiais.

2) data/02_staging
   Primeira cópia organizada dos dados brutos. Aqui o código ainda evita transformar muito os dados. A ideia é padronizar nomes de arquivos, remover duplicatas exatas e deixar tudo pronto para a transformação.

3) data/03_interim
   Dados intermediários já com tipos e nomes mais padronizados. Por exemplo: números convertidos, textos normalizados, colunas renomeadas e bases anuais unificadas.

4) data/04_curated
   Base curada. Aqui os dados já estão prontos para análise, com aliases, targets auxiliares, regiões, CINE, recorte 2019–2021 etc.

5) data/05_analysis
   Bases analíticas descritivas: funil, candidatos únicos, taxas etc.

6) data/06_abt
   ABT significa Analytical Base Table. É a base de modelagem: uma tabela em que cada linha é uma inscrição e cada coluna é uma variável que poderá entrar nos modelos. O código gera ABT binária e ABT ternária.

7) models/
   Modelos treinados salvos em disco com joblib, junto com metadados e métricas.

8) reports/
   Logs, diagnósticos e resultados intermediários.

9) article/
   Pacote final com tabelas, figuras e apêndices usados no artigo.

O arquivo main.py é o ponto de entrada. Ele funciona como um CLI, ou seja, uma interface de linha de comando. Você executa comandos como:

    python3 main.py pipeline all
    python3 main.py analysis all
    python3 main.py abt binaria
    python3 main.py modeling logit --force
    python3 main.py article modelagem
    python3 main.py export article --clean

O main.py não contém os algoritmos principais. Ele chama os módulos dentro de src/.

3. COMO O main.py EXECUTA O FLUXO
=================================================

O main.py lê sys.argv, que é a lista de argumentos passados no terminal. Por exemplo:

    python3 main.py modeling logit --force

nesse caso:

    sys.argv[0] = "main.py"
    sys.argv[1] = "modeling"
    sys.argv[2] = "logit"
    sys.argv[3] = "--force"

O main.py usa funções auxiliares:

    def tem_flag(nome: str) -> bool:
        return nome in sys.argv

Isso verifica se uma flag aparece no comando. Exemplo: tem_flag("--force") retorna True quando o comando contém --force.

    def valor_flag(nome: str, padrao=None):
        if nome not in sys.argv:
            return padrao
        indice = sys.argv.index(nome)
        if indice + 1 >= len(sys.argv):
            return padrao
        proximo = sys.argv[indice + 1]
        if proximo.startswith("--"):
            return padrao
        return proximo

Essa função pega o valor depois de uma flag. Exemplo:

    python3 main.py abt ternaria --recorte medicina

valor_flag("--recorte", "geral") retorna "medicina".

O main.py valida opções como recorte, target, avaliação, experimento e profundidade. Por exemplo:

    def obter_recorte(padrao: str = "geral") -> str:
        recorte = valor_flag("--recorte", padrao)
        if recorte == "general":
            recorte = "geral"
        if recorte not in ["geral", "medicina"]:
            print(f"Recorte inválido: {recorte}")
            sys.exit(1)
        return recorte

A lógica é simples: o comando aceita apenas "geral" ou "medicina". Se o usuário digitar outra coisa, o programa para.

=================================================
4. TEORIA ESSENCIAL DOS MODELOS E DO PIPELINE DO SCIKIT-LEARN
=================================================

Antes de explicar os arquivos de modelagem, é importante entender três objetos usados pelo scikit-learn:

1) Pipeline
2) ColumnTransformer
3) Estimador final, como LogisticRegression ou DecisionTreeClassifier

-------------------------------------------------
4.1. O que é Pipeline?
-------------------------------------------------

No scikit-learn, Pipeline é uma sequência de etapas. Em vez de você fazer manualmente:

    X_limpo = preprocessar(X)
    modelo.fit(X_limpo, y)
    previsao = modelo.predict(X_limpo_teste)

você monta:

    Pipeline(
        steps=[
            ("preprocessador", alguma_transformacao),
            ("modelo", algum_modelo),
        ]
    )

No seu código aparece assim, na regressão logística:

    def criar_pipeline(numericas: list[str], categoricas: list[str]) -> Pipeline:
        return Pipeline(
            steps=[
                ("preprocessador", criar_preprocessador(numericas, categoricas)),
                ("modelo", criar_modelo()),
            ]
        )

O que isso significa?

- Primeiro, os dados passam pelo preprocessador.
- Depois, os dados transformados vão para o modelo.
- Quando você chama modelo.fit(X_train, y_train), o pipeline faz automaticamente:
  1. preprocessador.fit_transform(X_train)
  2. modelo.fit(X_train_transformado, y_train)

- Quando você chama modelo.predict_proba(X_test), o pipeline faz automaticamente:
  1. preprocessador.transform(X_test)
  2. modelo.predict_proba(X_test_transformado)

Isso evita erro comum: aplicar transformação diferente no treino e no teste. O pipeline garante que o mesmo tratamento aprendido no treino seja usado no teste.

-------------------------------------------------
4.2. O que é ColumnTransformer?
-------------------------------------------------

A base tem variáveis numéricas e categóricas.

Exemplos de numéricas:

- renda_per_capita
- gap
- renda_gap
- idade
- nota_corte_gp

Exemplos de categóricas:

- curso
- turno
- região
- sexo
- raça/cor
- subárea
- UF

Você não trata número e categoria do mesmo jeito. O ColumnTransformer permite dizer:

- Para colunas numéricas, faça uma sequência de tratamentos.
- Para colunas categóricas, faça outra sequência.

No código da regressão logística:

    def criar_preprocessador(numericas: list[str], categoricas: list[str]) -> ColumnTransformer:
        numeric_transformer = Pipeline(
            steps=[
                ("imputer", SimpleImputer(strategy="median")),
                ("scaler", StandardScaler()),
            ]
        )

        categorical_transformer = Pipeline(
            steps=[
                ("imputer", SimpleImputer(missing_values=np.nan, strategy="constant", fill_value="Não informado")),
                (
                    "onehot",
                    OneHotEncoder(
                        handle_unknown="ignore",
                        sparse_output=True,
                        min_frequency=20,
                    ),
                ),
            ]
        )

        transformers = []
        if numericas:
            transformers.append(("num", numeric_transformer, numericas))
        if categoricas:
            transformers.append(("cat", categorical_transformer, categoricas))

        return ColumnTransformer(
            transformers=transformers,
            remainder="drop",
            sparse_threshold=0.3,
            verbose_feature_names_out=True,
        )

Explicando cada parte:

SimpleImputer(strategy="median")
  Preenche valores ausentes em colunas numéricas usando a mediana da coluna. Exemplo: se idade está vazia, usa a mediana das idades do treino. Mediana é o valor central. Ela é menos sensível a valores extremos que a média.

StandardScaler()
  Padroniza as variáveis numéricas. Ele transforma cada valor em algo como:

      valor_padronizado = (valor - média) / desvio padrão

  Isso é importante para regressão logística porque variáveis em escalas muito diferentes podem atrapalhar o ajuste. Renda pode estar em milhares, idade em dezenas, nota em centenas. A padronização coloca tudo em escala comparável.

SimpleImputer(strategy="constant", fill_value="Não informado")
  Para categorias ausentes, preenche com o texto "Não informado". Assim o modelo não perde a linha inteira só porque uma categoria faltou.

OneHotEncoder(handle_unknown="ignore", min_frequency=20)
  Transforma categorias em colunas 0/1.

  Exemplo: turno = "MANHÃ", "TARDE", "NOITE" vira:

      turno_MANHÃ  turno_TARDE  turno_NOITE
      1            0            0
      0            1            0
      0            0            1

  handle_unknown="ignore" significa: se no teste aparecer uma categoria que não apareceu no treino, ignore em vez de quebrar o programa.

  min_frequency=20 significa: categorias muito raras são agrupadas/consideradas como infrequentes pelo encoder. Isso evita criar milhares de colunas para categorias quase inexistentes.

remainder="drop"
  Colunas que não foram listadas em numericas ou categoricas são descartadas. Isso evita que variáveis indevidas entrem sem querer.

sparse_threshold=0.3
  Permite saída esparsa quando há muitas colunas 0/1. Isso economiza memória, especialmente após one-hot encoding.

verbose_feature_names_out=True
  Faz as colunas transformadas ficarem com prefixo, como num__renda_per_capita ou cat__turno_NOITE. Isso ajuda depois na interpretação dos coeficientes/importâncias.

-------------------------------------------------
4.3. Por que a árvore não usa StandardScaler?
-------------------------------------------------

Na árvore por profundidade, o preprocessador numérico é:

    numeric_transformer = Pipeline(
        steps=[("imputer", SimpleImputer(strategy="median"))]
    )

Não tem StandardScaler. Isso faz sentido.

Árvore de decisão não precisa que renda, idade e nota estejam na mesma escala, porque ela trabalha com cortes do tipo:

    renda_per_capita <= 1200?
    gap <= -50?
    nota_corte_gp <= 700?

A escala não atrapalha a árvore da mesma forma que pode atrapalhar modelos lineares.

-------------------------------------------------
4.4. O que é predict_proba?
-------------------------------------------------

Muitos modelos de classificação não retornam só uma classe. Eles também podem retornar probabilidades:

    modelo.predict_proba(X)

Exemplo binário:

    [0.85, 0.15]

Isso pode significar:

    85% de probabilidade de não contratado
    15% de probabilidade de contratado

No código, para regressão logística binária:

    proba_teste = modelo.predict_proba(X_teste)[:, 1]

O [:, 1] pega a probabilidade da classe positiva, que é target 1 = contratada.

No ternário, predict_proba retorna três colunas:

    classe 0 = lista de espera
    classe 1 = não contratado
    classe 2 = contratada

-------------------------------------------------
4.5. O que é holdout 80/20?
-------------------------------------------------

O código usa:

    train_test_split(
        indices,
        test_size=TEST_SIZE,
        random_state=RANDOM_STATE,
        stratify=y,
        shuffle=True,
    )

Explicação:

train_test_split
  Divide os registros em treino e teste.

test_size=0.20
  20% para teste, 80% para treino.

random_state=42
  Semente fixa para reproduzir a mesma divisão.

stratify=y
  Preserva a proporção das classes no treino e no teste. Isso é importante porque a base é desbalanceada. Sem estratificação, o teste poderia ficar com proporção diferente de contratados.

shuffle=True
  Embaralha antes de dividir.

O holdout mede desempenho em dados que o modelo não viu no treino. Isso é mais honesto do que avaliar no mesmo conjunto usado para treinar.

-------------------------------------------------
4.6. O que é in_sample?
-------------------------------------------------

Quando avaliacao == "in_sample", o código retorna os mesmos índices para treino e teste:

    if avaliacao == "in_sample":
        return indices, indices, "in_sample"

Isso significa que treina e avalia nos mesmos dados.

Para que serve?

- Diagnóstico.
- Comparar ajuste interno.
- Gerar probabilidades previstas no conjunto completo.

Mas não deve ser interpretado como desempenho fora da amostra. Para desempenho preditivo, o holdout 80/20 é mais apropriado.

=================================================
5.7. src/pipeline/transform/limpeza_tipos_fies.py
=================================================

Objetivo: transformar os CSVs padronizados do staging em Parquet limpo, com nomes de colunas padronizados e tipos corrigidos.

Este arquivo separa inscrições e ofertas.

Funções importantes:

parse_staging_filename(path)
  Lê o nome do arquivo e descobre tipo, ano e semestre.

limpar_nome_coluna(col)
  Padroniza nome de coluna. Normalmente transforma para minúsculo, remove acentos/espaços estranhos e deixa mais fácil mapear.

limpar_texto(valor)
  Normaliza textos: remove espaços extras, padroniza strings vazias, possivelmente aplica uppercase.

converter_numero_br(serie)
  Converte número em formato brasileiro para número de verdade.

Exemplo:

    "1.234,56" -> 1234.56

Isso é importante porque microdados brasileiros muitas vezes usam vírgula como decimal.

coalescer_colunas_duplicadas(df)
  Quando duas colunas viram o mesmo nome depois da padronização, a função combina valores. A ideia de coalescer é: usar o primeiro valor não vazio entre colunas equivalentes.

transformar_inscricoes(df, ano_arquivo, semestre_arquivo, arquivo_origem)
  É a função central para inscrições.

Trecho importante:

    df.columns = [limpar_nome_coluna(col) for col in df.columns]
    df = df.rename(columns=MAPA_INSCRICOES)
    df = coalescer_colunas_duplicadas(df)

Explicação:

- limpa todos os nomes de colunas;
- renomeia para nomes canônicos com MAPA_INSCRICOES;
- resolve duplicidade de colunas.

Depois cria metadados:

    df["arquivo_origem"] = arquivo_origem
    df["ano_arquivo"] = ano_arquivo
    df["semestre_arquivo"] = semestre_arquivo

Isso permite rastrear de onde cada linha veio.

Para data de nascimento:

    df["data_nascimento"] = pd.to_datetime(
        df["data_nascimento"],
        errors="coerce",
        dayfirst=True,
    )

pd.to_datetime converte texto em data. errors="coerce" transforma valor inválido em NaT, em vez de quebrar. dayfirst=True indica formato brasileiro, como 31/12/2000.

Para números:

    for col in FLOAT_COLS_INSCRICOES:
        if col in df.columns:
            df[col] = converter_numero_br(df[col])

Ou seja, percorre colunas que devem ser numéricas e converte.

transformar_ofertas(...)
  Faz a mesma lógica para ofertas. Usa MAPA_OFERTAS e listas próprias de colunas numéricas/inteiras.

processar_arquivo(path)
  Decide se o arquivo é inscrição ou oferta, chama a transformação correta e salva como Parquet:

    df_out.to_parquet(caminho_saida, index=False)

Parquet é um formato binário eficiente para dados tabulares. É melhor que CSV para pipelines porque preserva tipos e lê mais rápido.

run()
  Processa todos os arquivos do staging.

O que esse arquivo faz certo?

- Não mistura inscrições e ofertas.
- Registra arquivo de origem.
- Converte números e datas em etapa própria.
- Salva em Parquet para as próximas etapas.

5.9. src/pipeline/transform/mestre_inep.py
=================================================

Objetivo: criar uma base mestre de cursos/instituições a partir do Censo da Educação Superior.

Por que isso existe?

O FIES pode ter informações de curso/instituição, mas o INEP/Censo da Educação Superior oferece cadastro mais padronizado. O código usa isso para enriquecer a base.

Funções importantes:

detectar_encoding_e_colunas(path)
  Tenta ler arquivo com encodings diferentes e detectar colunas. Encoding é a forma como caracteres são codificados. Em bases públicas brasileiras, pode aparecer UTF-8, Latin-1 etc.

selecionar_colunas_inep(df)
  Seleciona colunas úteis do cadastro de cursos.

ler_cadastro_cursos(path)
  Lê um arquivo de cursos do INEP.

padronizar_cadastro_cursos(df)

5.21. src/modeling/logit_binario_utils.py
=================================================

Este é um dos arquivos mais importantes.

Objetivo: treinar regressão logística binária para prever contratação entre NÃO CONTRATADO e CONTRATADA.

A regressão logística é um modelo de classificação. No binário, ela estima a probabilidade de classe 1, que aqui é CONTRATADA.

Teoria simples:

A regressão logística calcula algo como:

    z = b0 + b1*x1 + b2*x2 + ... + bk*xk

Depois transforma z em probabilidade:

    p = 1 / (1 + exp(-z))

Se p >= 0,5, o código classifica como 1. Se p < 0,5, classifica como 0.

No código:

FEATURE_BLOCKS
  Define quais variáveis podem entrar no modelo e se cada uma é numérica ou categórica.

Exemplo:

    "renda_per_capita": {"label": "Renda familiar per capita", "type": "numeric"}
    "opcao_curso": {"label": "Opção de curso", "type": "categorical"}

EXPERIMENTS
  Define E1 a E5.

E1 usa só:

- renda_per_capita
- gap
- renda_gap

E2 adiciona idade, nota de corte, opção de curso.
E3 adiciona ano, semestre, conceito, turno etc.
E4 adiciona subárea, região, natureza jurídica, raça/cor.
E5 usa tudo.

blocos_validos_para_experimento(df, experimento)
  Verifica quais colunas do experimento existem e têm dados úteis.

separar_tipos(blocos)
  Divide variáveis em numéricas e categóricas.

criar_preprocessador(numericas, categoricas)
  Monta ColumnTransformer com tratamento numérico e categórico.

Código-chave:

    numeric_transformer = Pipeline(
        steps=[
            ("imputer", SimpleImputer(strategy="median")),
            ("scaler", StandardScaler()),
        ]
    )

    categorical_transformer = Pipeline(
        steps=[
            ("imputer", SimpleImputer(missing_values=np.nan, strategy="constant", fill_value="Não informado")),
            ("onehot", OneHotEncoder(handle_unknown="ignore", sparse_output=True, min_frequency=20)),
        ]
    )

Isso significa:

- numéricas: preencher ausentes com mediana + padronizar;
- categóricas: preencher ausentes como “Não informado” + transformar categorias em colunas 0/1.

criar_modelo()
  Cria a regressão logística:

    LogisticRegression(
        solver="lbfgs",
        C=0.1,
        class_weight="balanced",
        max_iter=5000,
        tol=1e-4,
        random_state=42,
    )

Explicando:

solver="lbfgs"
  Algoritmo numérico usado para encontrar os coeficientes da regressão.

C=0.1
  Controla regularização. C menor significa regularização mais forte. Regularização evita coeficientes exagerados e ajuda a reduzir overfitting.

class_weight="balanced"
  Dá mais peso para a classe minoritária. Como contratada é menor, isso ajuda o modelo a não ignorar essa classe.

max_iter=5000
  Número máximo de iterações para o algoritmo convergir.

tol=1e-4
  Tolerância para parar otimização.

criar_pipeline()
  Junta preprocessador + modelo.

criar_split()
  Escolhe in_sample ou holdout 80/20.

preparar_xy(df, blocos)
  Monta X e y.

    X = variáveis explicativas
    y = target_binario

calcular_metricas(y_true, proba)
  Calcula métricas.

Código:

    y_pred = (proba >= 0.5).astype(int)
    matriz = confusion_matrix(y_true, y_pred, labels=[0, 1])

Se probabilidade >= 0,5, classifica como contratada.

Métricas:

roc_auc
  Mede capacidade de separar contratada e não contratada usando probabilidades.

accuracy
  Total de acertos.

balanced_accuracy
  Média do acerto por classe.

precision
  Quando previu contratada, quantas eram contratadas.

recall
  Das contratadas reais, quantas encontrou.

f1
  Equilíbrio entre precision e recall.

log_loss
  Mede qualidade probabilística. Penaliza previsões confiantes erradas.

confusion_matrix
  Gera tn, fp, fn, tp.

extrair_coeficientes(modelo)
  Pega coeficientes da regressão.

Coeficiente positivo significa que, mantendo o resto constante no modelo, aumento naquela variável transformada empurra probabilidade para classe 1. Coeficiente negativo empurra para classe 0. Como há one-hot e padronização, a interpretação precisa ser cautelosa.

ajustar_um_experimento(...)
  Faz o fluxo completo de um experimento:

1. escolhe blocos E1/E2/E3/E4/E5;
2. separa numéricas/categóricas;
3. monta X e y;
4. divide treino/teste;
5. cria pipeline;
6. treina com fit;
7. calcula predict_proba;
8. calcula métricas;
9. extrai coeficientes;
10. salva modelo e resultados.

run_modelagem(...)
  Roda todos os experimentos definidos.

Este arquivo está correto para regressão logística binária.

5.22. src/modeling/logit_ternario_utils.py
=================================================

Objetivo: treinar regressão logística multinomial para três classes.

Classes:

    0 = lista de espera
    1 = não contratado
    2 = contratada

Teoria:

A regressão logística multinomial é a extensão da regressão logística para mais de duas classes. Em vez de uma probabilidade, ela estima uma probabilidade para cada classe:

    P(lista de espera)
    P(não contratado)
    P(contratada)

A classe prevista é a de maior probabilidade.

O arquivo é parecido com logit_binario_utils, mas muda:

- target_col = target_ternario;
- métricas multiclasse;
- coeficientes por classe;
- ROC-AUC multiclasse OVR.

OVR significa One-vs-Rest, ou um contra o resto. Para calcular ROC-AUC com três classes, o código compara:

- lista de espera vs resto;
- não contratado vs resto;
- contratada vs resto;

e depois agrega.

Funções extras:

predicoes_por_proba(proba, classes)
  Escolhe a classe com maior probabilidade.

calcular_roc_auc(y_true, proba, classes)
  Calcula ROC-AUC multiclasse.

calcular_metricas(...)
  Calcula:

- roc_auc_ovr_weighted;
- accuracy;
- balanced_accuracy;
- precision_macro;
- recall_macro;
- f1_macro;
- precision_weighted;
- recall_weighted;
- f1_weighted;
- log_loss;
- matriz de confusão por par real/predito.

Macro vs weighted:

macro
  Calcula a métrica para cada classe e tira média simples. Cada classe pesa igual.

weighted
  Calcula a métrica por classe e pondera pelo tamanho da classe. Classes maiores pesam mais.

Por que F1 macro é importante?

Porque contratada é menor. Se usar só média ponderada, a classe maior pode esconder erros na classe menor.

extrair_coeficientes(modelo)
  Na multinomial, há coeficientes por classe. Um coeficiente ajuda a explicar como uma variável empurra a probabilidade relativa de determinada classe.

Este arquivo está correto para a tarefa ternária.

5.27. src/modeling/treeClassification_utils.py
=================================================

Objetivo: treinar árvores de decisão padrão, com profundidade fixa mais simples.

Teoria da árvore de decisão:

Uma árvore faz perguntas sucessivas aos dados. Exemplo:

    gap <= -100?
       sim -> provavelmente lista de espera
       não -> renda <= 1200?
              sim -> ...
              não -> ...

Cada nó da árvore faz um corte. A árvore escolhe cortes que reduzem a mistura de classes. O critério usado é Gini.

Impureza Gini:

- Gini baixo: nó mais puro, quase só uma classe.
- Gini alto: nó misturado.

O objetivo da árvore é dividir os dados para deixar os nós filhos mais puros.

Funções importantes:

normalizar_target(target)
  Aceita binario/ternario e padroniza.

target_config(target)
  Define classes e labels conforme target.

criar_preprocessador()
  Parecido com o das regressões, mas sem StandardScaler nas numéricas.

criar_modelo(n_train, recorte)
  Cria DecisionTreeClassifier.

Na versão padrão, usa profundidade fixa do arquivo.

criar_pipeline()
  Junta preprocessador + árvore.

calcular_metricas()
  Calcula métricas binárias ou ternárias.

feature_original(feature_transformada)
  Converte nome transformado pelo one-hot para variável original.

Exemplo:

    cat__turno_NOTURNO -> turno
    num__renda_per_capita -> renda_per_capita

extrair_importancias(modelo)
  Pega feature_importances_ da árvore.

Teoria:

feature_importances_ mede quanto cada variável transformada ajudou a reduzir impureza na árvore. Não é causalidade. É importância interna do modelo.

agregar_importancias_por_variavel()
  Como one-hot cria várias colunas para uma variável, o código soma importâncias por variável original.

Exemplo:

    cat__turno_MANHÃ
    cat__turno_NOITE
    cat__turno_TARDE

viram importância agregada de:

    turno

extrair_primeira_divisao()
  Descobre qual variável aparece na raiz da árvore. A raiz é a primeira pergunta da árvore, então é interpretativamente importante.

5.28. src/modeling/treeClassification_profundidade_utils.py
=================================================

Este é o arquivo central das árvores de decisão com profundidade 10, 14 e 19.

Ele é mais completo que treeClassification_utils.py.

No começo define:

    TREE_DEPTH_PROFILES = {
        10: {...},
        14: {...},
        19: {...},
    }

Cada perfil define profundidade máxima e pré-poda mínima.

Profundidade máxima:
  Número máximo de níveis da árvore. Quanto maior, mais complexa a árvore.

Pré-poda:
  Regras que impedem a árvore de crescer demais. Exemplo: não permitir folhas com poucos registros.

Funções importantes:

validar_profundidade(profundidade)
  Só aceita 10, 14 ou 19.

target_config(target)
  Define se o modelo é binário ou ternário.

criar_preprocessador(numericas, categoricas)
  Numéricas: SimpleImputer mediana.
  Categóricas: SimpleImputer + OneHotEncoder.

min_leaf_dinamico(n_train, recorte, profundidade)

Código:

    return int(max(profile["min_samples_leaf_min"], round(n_train * 0.0005)))

Isso define o mínimo de amostras por folha.

Exemplo: se n_train = 1.000.000,

    n_train * 0.0005 = 500

Então a folha precisa ter pelo menos 500 registros, porque max(400, 500) = 500.

Por que isso é bom?

Impede folhas minúsculas, que seriam regras específicas demais e poderiam gerar overfitting.

min_split_dinamico(...)

Código:

    leaf = min_leaf_dinamico(...)
    return int(max(profile["min_samples_split_min"], 2 * leaf))

Para dividir um nó, exige pelo menos o dobro do tamanho mínimo de folha. Faz sentido: se uma divisão cria dois filhos, cada um deve poder ter pelo menos o mínimo.

criar_modelo(...)

Código:

    DecisionTreeClassifier(
        criterion="gini",
        splitter="best",
        max_depth=profundidade,
        min_samples_leaf=leaf,
        min_samples_split=split,
        class_weight="balanced",
        random_state=RANDOM_STATE,
    )

Explicando:

criterion="gini"
  Usa impureza Gini para escolher cortes.

splitter="best"
  Escolhe o melhor corte encontrado em cada nó.

max_depth=profundidade
  Limita complexidade.

min_samples_leaf=leaf
  Evita folhas pequenas.

min_samples_split=split
  Evita dividir nós pequenos demais.

class_weight="balanced"
  Dá mais peso a classes minoritárias.

random_state=42
  Reprodutibilidade.

calcular_metricas(target, y_true, proba, classes)
  Calcula métricas. Para binário, usa classe positiva contratada. Para ternário, usa macro/weighted.

extrair_importancias()
  Pega importâncias transformadas.

validar_importancias_normalizadas()
  Verifica se a soma das importâncias está coerente. Isso evita erro de agregação.

agregar_importancias_por_variavel()
  Soma importâncias do one-hot para voltar à variável original.

extrair_regras_arvore()
  Usa export_text para gerar regras em texto.

export_text
  Função do scikit-learn que transforma a árvore em regras legíveis. Exemplo:

    |--- gap <= -120
    |   |--- class: lista de espera
    |--- gap > -120
    |   |--- renda <= 1500
    |   |--- ...

ajustar_um_experimento()
  Fluxo completo de uma árvore:

1. escolhe variáveis E1-E5;
2. prepara X/y;
3. divide treino/teste;
4. cria pipeline;
5. treina árvore;
6. calcula probabilidades;
7. calcula métricas;
8. extrai importâncias;
9. agrega importâncias;
10. extrai primeira divisão/regras;
11. salva modelo, métricas e artefatos.

Este arquivo está bem feito e é o núcleo das árvores por profundidade.

7. EXPLICAÇÃO DAS MÉTRICAS COM BASE NO CÓDIGO
=================================================

No binário, as classes são:

    0 = não contratado
    1 = contratada

A matriz de confusão é:

    matriz = confusion_matrix(y_true, y_pred, labels=[0, 1])

Ela gera:

    tn = real 0, predito 0
    fp = real 0, predito 1
    fn = real 1, predito 0
    tp = real 1, predito 1

Acurácia:

    (tp + tn) / total

Precision:

    tp / (tp + fp)

Pergunta: quando o modelo disse contratada, quantas eram contratadas?

Recall:

    tp / (tp + fn)

Pergunta: das contratadas reais, quantas o modelo encontrou?

F1:

    2 * precision * recall / (precision + recall)

Equilibra precision e recall.

Balanced accuracy:

    média do recall de cada classe

Serve para classe desbalanceada.

ROC-AUC:

Mede se o modelo atribui probabilidades maiores para positivos reais do que para negativos reais. Não depende de um único corte 0,5.

Log loss:

Penaliza probabilidades erradas. Exemplo: se o modelo dá 0,99 para contratada, mas era não contratado, a punição é alta.

No ternário, macro significa:

    calcula métrica em cada classe e tira média simples

Weighted significa:

    calcula métrica em cada classe e tira média ponderada pelo número de registros da classe

=================================================
8. O QUE VOCÊ PRECISA SABER FALAR SE PERGUNTAREM
=================================================

Pergunta: o que o pipeline faz?
Resposta: baixa/recebe microdados brutos, faz staging, limpa tipos e nomes, unifica anos, cruza informações de curso/INEP/CINE, cura a base, gera bases descritivas, monta ABTs, treina modelos e exporta artefatos do artigo.

Pergunta: o que é ABT?
Resposta: é a tabela final de modelagem. Cada linha é uma inscrição e as colunas são variáveis usadas pelo modelo, além do target.

Pergunta: qual diferença entre binário e ternário?
Resposta: binário compara não contratado contra contratado, focando etapa contratual. Ternário inclui lista de espera, não contratado e contratado, representando fluxo mais amplo.

Pergunta: por que usar regressão logística?
Resposta: é modelo clássico e interpretável para classificação. Serve como referência.

Pergunta: por que árvore de decisão?
Resposta: é mais flexível e permite interpretar variáveis importantes por divisões da árvore.

Pergunta: por que class_weight="balanced"?
Resposta: porque as classes são desbalanceadas. Ele aumenta peso da classe menor para o modelo não ignorar contratados.

Pergunta: o que é OneHotEncoder?
Resposta: transforma categorias em colunas 0/1 para o modelo conseguir usar variáveis como curso, turno, região e UF.

Pergunta: o que é SimpleImputer?
Resposta: preenche valores ausentes. Numéricas com mediana; categóricas com "Não informado".

Pergunta: o que é StandardScaler?
Resposta: padroniza variáveis numéricas para média 0 e desvio 1. Ajuda modelos lineares como regressão logística.

Pergunta: por que não padroniza na árvore?
Resposta: árvore usa cortes, então não precisa da mesma escala numérica.

Pergunta: o que é ROC-AUC?
Resposta: mede capacidade de separação das classes a partir das probabilidades.

Pergunta: o que é F1 macro?
Resposta: é a média do F1 das classes, dando peso igual para lista de espera, não contratado e contratado.

Pergunta: isso prova causalidade?
Resposta: não. O código gera modelos preditivos e associações, não inferência causal.
