1. COMO O PROJETO FUNCIONA NO FLUXO REAL
===============================================================================

O projeto é organizado como um pipeline de dados e modelagem. A ideia geral é:

Dados brutos oficiais
  -> staging
  -> transformação e padronização
  -> curadoria
  -> bases analíticas descritivas
  -> ABTs de modelagem
  -> modelos estatísticos/de machine learning
  -> tabelas, figuras e apêndices
  -> pacote final article/

O arquivo main.py é o ponto de entrada. Ele funciona como CLI, ou seja, uma interface de linha de comando. Em vez de rodar cada módulo manualmente, você chama comandos como:

python3 main.py pipeline all
python3 main.py analysis all
python3 main.py article all
python3 main.py abt binaria
python3 main.py abt ternaria --recorte geral
python3 main.py modeling logit --force
python3 main.py modeling tree-depth --force
python3 main.py article modelagem
python3 main.py export article --avaliacao in_sample --clean

O README descreve esse fluxo de forma coerente.

Etapas principais:

1) init/check
   Cria estrutura de pastas e verifica caminhos.

2) pipeline all
   Executa staging, transformações e curadoria. Esta é a parte de ETL: Extract, Transform, Load.

3) analysis all
   Gera bases descritivas: candidatos únicos, funil do processo seletivo e taxas.

4) article all
   Gera produtos descritivos do artigo: fluxo, taxas, tabelas de distribuição, matrizes renda x desempenho, financiamento/coparticipação.

5) abt binaria / abt ternaria
   Gera as bases de modelagem. ABT significa Analytical Base Table: uma tabela preparada para treino de modelos, com uma linha por observação, variáveis preditoras e target.

6) modeling logit / modeling tree-depth
   Treina regressão logística e árvores de decisão.

7) article modelagem
   Gera tabelas, figuras e apêndices dos modelos.

8) export article
   Copia e organiza os resultados finais em article/.

Teoria por trás: isso é uma arquitetura de pipeline reprodutível. A vantagem é separar dados brutos, dados intermediários, bases analíticas e resultados finais. Essa separação evita que você misture limpeza de dados, análise e redação do artigo em um único script confuso.

2. TEORIA GERAL DAS TÉCNICAS USADAS
===============================================================================

2.1 ABT
-------
ABT é uma tabela analítica para modelagem. No projeto, existem duas ABTs centrais:

- ABT binária: NÃO CONTRATADO = 0; CONTRATADA = 1.
  Ela olha a etapa contratual.

- ABT ternária: LISTA DE ESPERA = 0; NÃO CONTRATADO = 1; CONTRATADA = 2.
  Ela olha o fluxo mais amplo, separando a barreira acadêmica inicial da etapa contratual.

2.2 Gap/desempenho relativo à nota de corte
--------------------------------------------
O código calcula:

gap = media_enem - nota_corte_gp

Se gap é positivo, o candidato ficou acima da nota de corte do grupo de preferência.
Se gap é negativo, ficou abaixo.

Também calcula:

renda_gap = renda_per_capita * gap

Essa interação tenta representar que o efeito do desempenho pode mudar conforme a renda, e vice-versa.

2.3 Pré-processamento do scikit-learn
-------------------------------------
Nos modelos, o código usa Pipeline e ColumnTransformer.

Pipeline é uma sequência de passos: primeiro transforma os dados, depois treina o modelo. Isso evita vazamento entre treino e teste e deixa o processo reprodutível.

ColumnTransformer aplica transformações diferentes por tipo de coluna:
- numéricas: imputação por mediana e, na regressão logística, padronização;
- categóricas: imputação com “Não informado” e OneHotEncoder.

SimpleImputer preenche valores ausentes.
StandardScaler coloca variáveis numéricas em escala parecida.
OneHotEncoder transforma categorias em colunas binárias. Exemplo: turno = NOITE vira uma coluna turno_NOITE.

2.4 Regressão logística
-----------------------
A regressão logística é um modelo de classificação. No binário, estima probabilidade de uma inscrição ser contratada. No ternário, a versão multinomial estima probabilidades para lista de espera, não contratação e contratação.

O código usa class_weight='balanced', que aumenta o peso das classes menores. Isso é importante porque contratação é minoria.

2.5 Árvore de decisão
---------------------
A árvore de decisão separa os dados por regras sucessivas. Exemplo abstrato:

se gap <= X -> um ramo
se gap > X -> outro ramo

Ela escolhe divisões que deixam os grupos mais “puros”, isto é, mais homogêneos em relação à classe. O código usa critério Gini, que mede impureza.

A profundidade controla complexidade. Profundidade 10, 14 e 19 significam árvores progressivamente mais flexíveis. Árvores mais profundas podem capturar padrões mais complexos, mas também podem sobreajustar.

2.6 Holdout 80/20
-----------------
O código separa 80% dos registros para treino e 20% para teste, com estratificação. Estratificação significa preservar a proporção das classes no treino e no teste.

2.7 Métricas
------------
Acurácia: percentual total de acertos. Pode enganar em base desbalanceada.

Acurácia balanceada: média do desempenho por classe. Melhor quando as classes têm tamanhos muito diferentes.

Precisão: quando o modelo prevê “contratada”, quantas realmente eram contratadas.

Revocação/recall: de todas as contratadas reais, quantas o modelo conseguiu encontrar.

F1-score: média harmônica entre precisão e revocação.

F1 macro: calcula F1 por classe e tira média simples, dando peso igual a cada classe.

ROC-AUC: mede capacidade de separação entre classes. Valor 0,5 é próximo de aleatório; quanto mais perto de 1, melhor.

Matriz de confusão: mostra acertos e erros por classe.

2.8 Probabilidades previstas
----------------------------
O artigo de Educação usa probabilidades previstas porque elas são mais interpretáveis para políticas públicas. Em vez de dizer só “o modelo acertou X”, a figura pode mostrar: para determinada faixa de renda e desempenho, qual a probabilidade prevista de lista de espera, não contratação ou contratação.

7. OS ALGORITMOS ESTÃO CERTOS?
===============================================================================

Sim, no essencial, os algoritmos estão implementados corretamente.

Regressão logística binária:
- usa target 0/1;
- separa X e y;
- pré-processa variáveis;
- treina LogisticRegression;
- calcula probabilidades;
- calcula métricas adequadas;
- salva modelo e métricas.

Regressão logística multinomial:
- usa target com três classes;
- usa multi_class='multinomial';
- calcula probabilidades para cada classe;
- calcula ROC-AUC OVR ponderado e F1 macro/weighted;
- salva resultados por experimento.

Árvore de decisão:
- usa DecisionTreeClassifier;
- usa class_weight balanced;
- controla profundidade;
- calcula métricas;
- extrai importâncias e primeira divisão;
- salva regras textuais.

Holdout:
- usa train_test_split com stratify=y;
- isso preserva a proporção das classes.

Métricas:
- estão adequadas para classes desbalanceadas;
- F1 macro no ternário é uma escolha correta;
- ROC-AUC OVR ponderado no multiclasse é aceitável;
- matriz de confusão sustenta interpretação de erros.

Probabilidades previstas:
- fazem sentido para interpretação substantiva;
- são melhores para artigo de política pública do que apenas coeficientes técnicos.

8. POSSÍVEIS PERGUNTAS DO PROFESSOR E RESPOSTAS
===============================================================================

Pergunta: O que o repositório faz?
Resposta: Ele automatiza todo o fluxo da pesquisa: baixa/recebe dados brutos, padroniza, cruza com INEP/CINE, cria bases analíticas, treina modelos e exporta tabelas/figuras.

Pergunta: O que é ABT?
Resposta: É a tabela final usada para modelagem. Ela já tem target e variáveis preditoras em formato adequado.

Pergunta: Qual diferença entre binário e ternário?
Resposta: O binário compara não contratação e contratação, focando na etapa contratual. O ternário inclui lista de espera, então representa também a barreira acadêmica inicial.

Pergunta: Por que regressão logística?
Resposta: Porque é um modelo clássico, interpretável e adequado para classificação. Serve como base de comparação.

Pergunta: Por que árvore de decisão?
Resposta: Porque permite capturar relações não lineares e também interpretar variáveis importantes.

Pergunta: O que é class_weight balanced?
Resposta: É uma forma de compensar o desbalanceamento das classes, dando mais peso às classes menores durante o treino.

Pergunta: Por que não usar só acurácia?
Resposta: Porque contratação é minoria. Um modelo poderia acertar muito a classe majoritária e ainda ir mal na classe de interesse.

Pergunta: F1 macro significa o quê?
Resposta: Calcula F1 separadamente para cada classe e tira a média simples. Isso evita que a classe maior domine a avaliação.

Pergunta: O que é ROC-AUC?
Resposta: Mede capacidade de separação do modelo entre classes. Quanto mais perto de 1, melhor.

Pergunta: Isso prova causalidade?
Resposta: Não. Mostra associação e capacidade preditiva. O próprio código e o artigo devem interpretar como associação.

Pergunta: O código está certo?
Resposta: Sim, os algoritmos estão implementados corretamente. O cuidado maior é explicar bem o recorte da Modalidade I e usar a avaliação correta ao exportar resultados.
